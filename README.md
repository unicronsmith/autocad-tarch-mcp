# autocad-tarch-mcp

让 Claude Code 在 Windows 上直接读、识别、画 AutoCAD 图纸，重点是**天正图**：墙、门窗、柱、尺寸标注、引注、标高、管线这些天正对象，在没装天正的环境里只是读不出内容的代理对象。

- **天正图识别**：调本机天正建筑 T30，在天正进程里把每个天正对象分解一遍、读一遍属性，再导出天正3。出来的是按对象归好的识别结果 —— 每个对象画了什么字、尺寸值多少、墙厚墙高、门窗编号和洞口尺寸、管径 —— 外加门窗表、墙、柱、房间、管线这些汇总表
- **自带核对**：原图、识别记录、天正自己导出的天正3 三方逐项对（对象齐全、每条字对得上、尺寸值一致、原文拼得回、不丢字不多字），每张图给「通过 / 不通过」，线条画法不同的地方单独列出来
- **普通图纸**：文字（含块属性、块内文字、标注改写、多重引线、代理图形里的文字）、图元明细、图层、块、扩展数据
- **画图**：15 类图元、样式、布局、出 PDF
- 读图、画图全程无头（不开 AutoCAD 窗口）；只有天正识别和尺寸标注要用到 AutoCAD 窗口

## 部署

前提（脚本只检查，不替你装）：

| 要有 | 说明 |
|---|---|
| Windows 10/11 | |
| AutoCAD 2025 完整版 | 简体中文版。LT 不行（装不了天正，也没有 COM）；别的版本见下面「换 AutoCAD 版本」 |
| 天正建筑 T30 正式版 | 至少手动启动过一次；免费的 T30 插件不行，它不能分解、导出天正对象 |
| Python 3.10+ | `winget install Python.Python.3.12` |
| Git | `winget install Git.Git`，Claude Code 在 Windows 上也要用它 |

三步：

```powershell
git clone https://github.com/unicronsmith/autocad-tarch-mcp.git
cd autocad-tarch-mcp
powershell -ExecutionPolicy Bypass -File install.ps1
```

`install.ps1` 做四件事：装 Python 依赖 → 没有 Claude Code CLI 就用官方脚本装上 → 把 MCP server 注册成 `autocad`（user scope）→ 跑环境体检。可以重复运行。

装完验收（第三条会拉起一次天正 AutoCAD；开发机上三条分别是 4 秒、6 秒、23 秒）：

```powershell
python mcp\doctor.py           # 环境体检，缺什么照原样说
python mcp\selftest.py         # 读图、画图回归
python mcp\tarch_selftest.py   # 天正识别端到端：自带样例图 → 记录 → 天正3 → 核对 → 识别
```

AutoCAD、天正的安装位置从注册表读。装了多个版本或想指定，设环境变量 `ACAD_DIR`、`TARCH_DIR`。

更新：`git pull` 之后重跑 `install.ps1`。

### 换 AutoCAD 版本

天正识别靠一个加载进 AutoCAD 的小插件（`mcp/tchdump`），仓库里带的是给 AutoCAD 2025 编好的。别的版本 `doctor.py` 会告诉你缺插件，并给出编译命令（要装 .NET SDK）。2024 及更早的 AutoCAD 用的是 .NET Framework，这个插件工程编不了。

## 用法

到放图纸的目录里启动 `claude`，直接说要做什么，例如：

- 「识别一下 `某某.dwg`，列出门窗表和所有尺寸」
- 「读一下 `某某.dwg`，这张图讲了什么」
- 「把这个目录的天正图全部识别一遍并核对」
- 「按这份数据画一张平面图，出 A2 的 PDF」

也可以不经过 Claude，直接跑脚本（都断点续跑）：

```powershell
# 1. 普查 + 记录每个天正对象 + 导出天正3
python mcp\tarch_t3.py <图纸目录> <产物目录>
# 2. 原图 / 记录 / 天正3 三方核对：每张图一个结论
python mcp\tarch_verify.py <图纸目录> <产物目录>
# 3. 整理成识别结果：每张图一个 <名>_识别.json（核对里几何对不上的对象会被标出来）
python mcp\tarch_recognize.py <图纸目录> <产物目录>
# 全部文字（含非天正的）：有天正3 的图读天正3
python mcp\batch_text.py <图纸目录> <文字产物目录> --t3 <产物目录>
```

每张天正图的产物（都在产物目录里，镜像图纸目录的结构）：

| 文件 | 内容 |
|---|---|
| `<名>_识别.json` | 识别结果：按对象的文字、原文、属性、尺寸值；汇总表 |
| `<名>_tch.json` | 完整记录：每个对象分解出的全部图元（坐标）和全部属性，按句柄查 |
| `<名>_t3.dwg` | 天正3：不含天正对象的普通 DWG，任何 AutoCAD 都能开 |

其余脚本和每条通道的坑见 [CLAUDE.md](CLAUDE.md)，那份文件同时是给 Claude Code 看的项目说明。

## 准不准

开发机上拿一个旧改项目的 42 张天正图（建筑、结构、给排水、电气，4929 个天正对象，35 个类）实测，2026-10-03：

| 核对项 | 结果 |
|---|---|
| 天正对象一个不漏 | 4929 / 4929 |
| 记录里的每条字在天正3 里对得上 | 5427 / 5427 |
| 尺寸标注的显示值与天正3 画出来的字相同 | 1219 / 1219 |
| 原文（图名、门窗编号、坐标、标高……）能从碎片拼回 | 2583 / 2583 |
| 原图看得见的字在天正3 里丢了的 | 0 |
| 天正3 里有、记录里没有的字和标注 | 0 |
| 乱码 | 0 |
| 线、圆、块参照这些几何图元对得上 | 6736 / 6865 |

内容项全对，42 张全部通过。几何对不上的 129 个图元在 12 个对象上，是「在内存里分解」和「图面显示」画法不同：
双跑楼梯的踏步线（分解出来是整个梯段宽，图面只画到扶手边）120 个，图名下划线 4 个，墙端封口线 3 个，
一个引出标注 2 个。这些对象在识别结果里有标记，要它们显示出来的样子就读天正3。

另有 11 个嵌套或空的对象分解不了（6 个楼梯里的方向箭头、5 个没有内容的空对象），识别结果里同样有标记。
反过来也有记录比天正3 全的：一个块里的 5 个老式标注天正3 没导出，记录里有。

每张图的结论都是当场核对出来的，不是按这张表推的 —— 换一批图，照样看那张图自己的「核对」。

## 天正识别时会发生什么

- 脚本会以管理员身份重跑自己（AutoCAD 带「以管理员身份运行」兼容标记时必须这样才连得上），UAC 没关的机器会弹一次确认框
- 屏幕上会出现天正 AutoCAD 窗口和「图形导出」对话框，脚本自己填、自己关，别去点
- 一张图开一个天正会话；只动脚本自己拉起的 AutoCAD，你开着的图纸不碰。实测一张 608 个对象的建筑图，从转换、核对到识别 35 秒
- 你自己开着 AutoCAD 时不要跑
- 原图只读：脚本操作的是产物目录里 `_work` 下的工作副本

## 不进仓库的东西

图纸和识别产物都不进这个仓库，`.gitignore` 排除了 `*.dwg`、`*.dxf`（自带的那张天正样例图除外，它是用天正命令画的，不是工程图）。
